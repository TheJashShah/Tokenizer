How did I make my tokenizers - An informal Blog

Introduction

After learning tokenization from this great video, I started my own project to learn the coding concepts of tokenization, train one myself on a relatively small amount of data, and then train multiple tokenizers with different parameters on sizable amount of texts. In this process, I made my own short tokenization tutorial in the form of a notebook, made a data collection tool to collect real data across multiple domains, experimented with different optimizations to make the process of training a tokenizer faster, and finally trained six tokenizers. This blog will cover all details, informally.

Tutorial

My tokenization tutorial can be found here. It is made as a short-form replica of the Karpathy's video, providing all the code snippets needed for a naive-version of the tokenizer widely used. It also provides theoretical context and some tangential discussion, which ultimately affects the design choices made to make the tokenizer.

The data that I use

Before making the tokenizer, I made a utility class called DataCollector that collects data for six languages (English, Hindi, French, German, Japanese and Spanish), and five programming languages (Python, C++, Rust, Java, Javascript) For the languages, data was collected from RSS news feeds in the particular language, and also from language-specific Wikipedia pages through a Huggingface dataset. For the programming languages, data was collected from popular github repositories with the majority of the code in that language. The code for the DataCollector class, and an example on how to use that class can be found in this repository. A Choice was made to allocate 60% of the text corpus to the Languages, and 40% to the programming languages. This choice was made to show a comparison between my tokenizers and the GPT-2 and GPT-4 tokenizers on languages, on how specific words tokenize.

Tokenizers and optimization

A primary parameter differentiating my tokenizers is the choice of the REGEX string used. There are two options, either the GPT-2 REGEX string, or the GPT-4 string. The algorithm used is the Byte-Pair-Encoding (BPE) algorithm, as to make a fair comparison to the GPT tokenizers. The final tokenizer code is a heavily optimized version of the naive method, using unique chunks, with chunk-frequency maps, and only sparse marges on the affected chunks. Read about the optimization process here.
